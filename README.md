# Agent Factory

可视化、实时、真能干活的 AI 一人公司。3D 办公室里每个部门一个房间，每个员工一个工位（桌子、显示器、键盘鼠标、办公椅）。你是老板，经理 Agent 负责拆解、派活、评审和审批，员工 Agent 在各自工位上真实地写代码、跑命令、操作浏览器。每台电脑屏幕实时同步 Agent 正在做的事。

## 快速开始

```bash
pnpm install
cp .env.example .env          # 可选：填 DEEPSEEK_API_KEY；也可以启动后在界面里配置模型
pnpm dev                      # 开发：前端 http://localhost:5173 ，后端 :8787
```

生产 / 服务器（单端口，前端由后端托管）：

```bash
pnpm start                    # 先构建前端，再启动 http://0.0.0.0:8787
```

部署到服务器时请设置 `ACCESS_TOKEN`，访问 `http://host:8787/?token=xxx`（会记住在浏览器里）。

### 第一次使用

- 打开页面后，右侧会显示新手引导：
  - 一键试用的示例目标；
  - 准备清单：接入模型、设置预算、开启消息提醒。
- **模型在界面里配置**：点顶栏的模型名（演示模式下显示「演示模式」），选服务商、填 Key、测试连接，保存后立即切换，不用重启。
  - 支持 DeepSeek、通义千问、Kimi、智谱、豆包、OpenAI、本机 Ollama，以及其他 OpenAI 兼容接口。
  - Key 保存在 `data/llm.json`（权限 600），界面上只显示掩码。
  - 界面保存的配置优先于 `.env`；随时可以切回演示模式。
- **下达目标可以从模板开始**：模板按公司业务不同，在 `company/profiles/*.json` 的 `goalTemplates` 里配置。【】里是需要换成自己内容的地方。
- **「先问清楚再开工」**：打开后，经理会先向你确认 1~3 个关键问题再派活。答复会记在目标上，后续每个环节都能看到。
- 目标交付待验收或完成时，右上角会弹出提醒，点「查看交付」直接打开交付页。

## 屏幕上显示的都是真的

| 屏幕 | 来源 |
|---|---|
| 终端 | 每个 Agent 一个真实的 bash PTY（node-pty），原始字节流推到前端 xterm.js |
| 浏览器 | 每个 Agent 一个 Playwright Chromium 页面，CDP `Page.startScreencast` 推送真实画面帧，点击位置有光标动画 |
| 编辑器 | 模型流式输出 `write_file` 参数时，增量解析出代码内容实时上屏（不是写完再播放动画） |
| 思考 | 模型流式输出的文字 / reasoning |

3D 办公室：左上角切换「全公司 / 各部门」；拖动旋转、滚轮缩放、右键平移；单击工位镜头走到员工身后看屏幕，再单击（或双击）打开全屏大屏，可切换终端 / 浏览器 / 编辑器 / 思考，暂停该员工、插话或下达指示。显示器上的画面是真实 DOM 贴在 3D 屏幕表面，会被前面的人和物体正确遮挡。

## 办公室与协作

- 平面布局：后排是经理室和各部门（落地窗），中间走廊，前排是会议室和茶水间（朝镜头一面是矮墙）。左上角可切换到任一区域。
- 员工默认是内置奶蛙（同一个形象，项圈颜色区分角色）；也可以换成自己导出的 GLB/FBX/OBJ 模型并带上动画，见 [company/models/README.md](company/models/README.md)，姿态跟随真实状态：打字、用鼠标、托下巴思考、等审批张望、空闲喝咖啡/刷手机、暂停打盹。
- 会走动：开会时走进会议室入座发言（大屏实时显示发言和纪要），请示时走到经理室，请教同事时走到对方工位，空闲时偶尔去茶水间。头顶有对话气泡。
- 协作工具：
  - 经理：`call_meeting`（召集会议，纪要存 `docs/meetings/` 并附在目标上）、`talk_to`（叫员工到经理室谈话）、`reassign_task`（改派）
  - 员工：`ask_manager`（当面请示）、`ask_colleague`（请教同事）、`reject_assignment`（任务不属于本岗位时退单）
- 被叫去开会/谈话的员工会在当前这一步做完后起身，回来后接着做原来的任务。

## 派单质量

- 每个角色有岗位职责卡（`description / responsibilities / outOfScope / deliverables`），所有 Agent 的提示词里都带岗位职责表。
- 经理按固定步骤规划：判断交付物类型 → 必要时开会对齐 → 派发（必须写验收标准）。
- 派单校验：每次派发会让模型以“派单审核员”身份对照职责表复核，派错岗位直接拦截并给出建议岗位；经理坚持原派法需 `force=true` 并说明理由。
- 员工提交时必须逐条自查验收标准，经理评审也对照验收标准。

## 工作流

```
老板下达目标(P0~P3) → 经理规划，create_subtask 派给角色（可设依赖）
  → 员工领取 → 干活（高风险操作自动发起审批）→ submit_for_review
  → 经理评审：approve / request_changes（返工超过 N 次自动升级给老板）
  → 子任务全部完成 → 经理 finalize_goal → 老板验收（通过 / 打回重规划）
```

- **优先级**决定调度顺序；P0 任务到达而同角色员工都在忙时，会让一名员工保存进度让出，做完 P0 后自动接着做原任务。
- **风险等级**决定谁来审批（和优先级是两个维度）：
  - R0：直接执行
  - R1（安装依赖、递归删除、丢弃改动…）：经理审批，经理拿不准可转给老板
  - R2（sudo、git push、发布、下载执行脚本、删除工作区外文件…）：必须老板审批
- 老板的手段：审批 / 驳回（可附指导意见）、回答请示、验收、调整优先级、取消任务、暂停单人或全员、给任意员工插话。

## 交付页与成本

- **交付页**：任务看板里点目标标题（或 📄 按钮）、验收卡片上点「查看交付」打开。一页里能看到：
  - 交付总结、耗时、花费、返工次数；
  - 产出文件，可以直接预览：网页在沙箱里运行，Markdown 渲染，代码、图片也能看，还能新窗口打开或下载；
  - 每个子任务的要求、验收标准、员工总结、评审意见；
  - 过程记录：审批决定、会议纪要。

  待验收时可以直接在交付页通过或打回。
  - 产出文件取自员工用 `write_file` / `edit_file` 写过的文件（`Task.artifacts`）。
  - 预览地址是 `/preview/<随机密钥>/…`，只读，密钥每次启动随机生成，只通过已鉴权的 WebSocket 下发。AI 生成的网页拿不到访问口令。
- **成本**：每次模型调用按员工、任务、目标、天记账，缓存命中的输入按更低单价计。数据存在 `data/usage.json`。
  - 顶栏显示今日花费和预算进度，点开可以看近 14 天走势、按员工和按目标的排行。
  - 单价用 `.env` 里的 `LLM_PRICE_*` 设置，默认值只是量级参考，请按你的账单核对。演示模式下 token 是估算值。
- **预算**：在「成本与预算」里设置每日预算和单目标预算，不填就是不限。
  - 超出每日预算：全公司自动暂停，「待我决策」里出现请示。同意就追加一份今日额度并恢复工作；驳回则保持暂停。
  - 超出单目标预算：只暂停这个目标的工作，其他目标照常。同意就追加一份额度，驳回则取消这个目标。

## 公司规则与消息推送

顶栏「规则」按钮，设置保存在 `data/settings.json`：

- **审批权限**：
  - R1 中风险操作可以设为直接放行、经理审批或我来审批。
  - R2 高风险操作可以设为经理审批或我来审批；经理自己的 R2 操作始终由老板审批。
  - 交付是由我验收，还是经理确认就算完成。
- **超时处理**：老板 N 分钟没处理时，
  - 操作审批一律自动驳回（安全默认），员工会换一种做法；
  - 请示可以设为授权经理自行判断，或继续等我；
  - 预算告警和交付验收始终等老板本人决定。

  自动处理的记录在「历史」里标注为「系统 超时自动…」。
- **批量审批**：同时有 2 个以上操作审批时，收件箱顶部可以一键全部批准或驳回（有 R2 会额外提醒）。
- **消息推送**：填飞书、企业微信或钉钉群机器人的 Webhook，系统会按地址自动识别平台；其他地址收到通用 JSON `{event,title,text,url}`。
  - 可选推送的事件：需要我决策、交付待验收、超出预算、目标完成、任务受阻。
  - 机器人请使用「关键词」安全设置，关键词填 `Agent Factory`；暂不支持「签名校验」。
  - 「发送测试消息」可以验证配置是否成功。

## 在钉钉里指挥公司

接入钉钉企业内部应用机器人（Stream 模式，不需要公网地址）后：

- 在群里 @ 机器人，或单聊机器人，可以下达目标、查看状态、查看待办、批准或驳回、给员工插话、暂停或复工；
- 需要你决策的事项会推送到你的单聊，直接回复指令就能处理。

只有管理员能派活和审批，其他人只能查询。配置方法见 [docs/DINGTALK.md](docs/DINGTALK.md)。

## 业务可插拔

公司的角色、员工、提示词、工具权限、风险规则都在 `company/profiles/*.json`。新增一个 JSON 就是一种新公司（例如内容工作室、调研团队），顶栏可以切换。

- `departments`：部门（`kind: office` 独立办公室 / `open` 开放办公区），每个部门在 3D 办公室里是一个房间；员工用 `agents[].departmentId` 归属部门。新增部门 = 加一条部门 + 若干角色和员工
- `roles[].tools`：工具组 `fs` / `fs_read` / `terminal` / `browser` / `worker` / `manager`
- `policy.rules`：按工具名 + 正则匹配参数，给出 R1 / R2
- `policy.maxReviewRounds`、`requireHumanAcceptance`：评审与验收策略（`requireHumanAcceptance` 只作为初始值；在界面「规则」里保存过之后，以界面设置为准）

## 目录

```
apps/server   Fastify + WebSocket；agent/runtime（Agent 循环）、workflow（任务流转）、factory（调度/抢占）、tools（终端/浏览器/文件/任务）
apps/web      React + zustand + three.js（@react-three/fiber）；3D 办公室、实时屏幕、收件箱、任务看板、日志
packages/shared  前后端共享类型与 WebSocket 协议
company/profiles 公司业务配置
workspace/    Agent 们共享的项目目录（git 仓库），KNOWLEDGE.md 是公司知识库
data/         任务、审批、对话上下文、事件日志、成本账本 usage.json（重启后可恢复）
```

## 注意

- Agent 的终端拥有运行服务的用户的权限。风险规则是护栏不是沙箱；在服务器上建议用独立用户或容器运行。
- `reasoning_content` 会随对话回传给模型；如果所用模型的 API 不接受该字段，去掉 `apps/server/src/llm/openai.ts` 中的赋值即可。
